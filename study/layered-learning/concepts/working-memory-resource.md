# Core idea

Working memory should be treated not only as a limited storage system, but as a limited processing resource whose effective burden depends on novelty, task demands, and allocation.

# Why it matters here

This concept supports the move from generic capacity language to the segment-level term `C_i`.
It also supports treating available processing as allocable rather than as a rigid item-count constraint.

# Key distinctions

- classical architecture versus flexible resource views
- fixed slot language versus graded precision language
- total capacity versus strategically allocated effective capacity

# Modeling implications

- `C_i` should not be treated as a purely verbal placeholder
- the model needs a clear interpretation of whether `C_i` is fixed, learner-specific, or context-sensitive
- later versions may need a cost for investing more effective resource

# Open questions

- Is `C_i` a hard bound or a soft budget?
- Should `C_i` vary across segments because of fatigue, motivation, or task priority?
- Does the model need a separate resource-cost term beyond current capacity subtraction?
